# Error Handling UI

> **Scope:** Validation, fallback, and recovery states  
> **Version:** 1.0  
> **Status:** Draft

## 1. Overview

Error handling should be explicit, calm, and actionable. The UI should tell users what went wrong, what it means, and what they can do next.

## 2. Patterns

- Inline field error.
- Toast notification.
- Error banner.
- Retry button.
- Fallback panel.
- Quota or rate limit modal.

## 3. Behavior

- Keep the error close to the affected control.
- Use clear next steps.
- Preserve user input where possible.
